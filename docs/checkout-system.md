# 结算系统

第七阶段把账户购物车转换为不可变的订单快照。React Hook Form 负责表单状态和即时反馈，Zod schema 同时用于浏览器与 Route Handler；服务端只接受配送地址、支付方式、显式确认信息和幂等标识，不接受客户端计算的订单总额。

## 页面流程

1. `/checkout` 校验 HttpOnly Cookie 会话，未登录用户跳转至 `/login?next=/checkout`。
2. 服务端读取账户默认地址和实时购物车，客户端完成 hydration 后切换到 Zustand 中的最新账户购物车。
3. 用户填写收件人、联系电话、地址、邮编和两位国家代码，可选择保存为默认地址。
4. 用户选择 Stripe 在线支付或货到付款，并勾选商品与金额确认。
5. 客户端提交已确认的商品 ID、数量、单价和币种作为并发校验条件。
6. 服务端重新读取 MongoDB 购物车和商品，不使用客户端数据生成订单金额。
7. 创建成功后按购物车版本条件清空购物车，并进入仅订单所有者可访问的确认页。

Stripe 选项在本阶段只创建 `pending` 待支付订单，不会创建 PaymentIntent 或发生扣款。

## API

### `POST /api/orders`

需要有效用户会话、匹配的 `Origin` 和签名 CSRF Token，请求体上限为 32 KB。

请求字段：

- `shippingAddress`：严格校验的地址对象。
- `paymentMethod`：`stripe` 或 `cash_on_delivery`。
- `saveAddress`：是否保存为账户默认地址。
- `confirmOrder`：必须明确为 `true`。
- `idempotencyKey`：浏览器生成的 UUID。
- `expectedItems`：用户刚确认的商品 ID、数量、单价和币种，仅用于检测变化。

成功响应返回订单 DTO、是否新建以及购物车是否已安全清空。响应不会暴露内部 `checkoutKey` 或 `cartVersion`。

## 服务端规则

- 空购物车不能创建订单。
- 一张订单只能使用一种币种。
- 商品必须仍然存在、上架且库存不少于确认数量。
- 商品集合、数量、实时单价或币种发生变化时返回 `CHECKOUT_CART_CHANGED`，客户端刷新购物车并要求重新确认。
- 订单商品名称、图片、单价、数量、小计、配送地址和总额均保存为快照。
- 总额必须是非负安全整数，并由实时商品小计汇总。
- 同一用户的 `idempotencyKey` 唯一，网络重试不会重复创建订单。
- 同一购物车 `updatedAt` 版本只能生成一张订单，可阻止不同幂等键对同一购物车重复下单。
- 购物车只在版本仍与结算开始时一致时清空，避免删除用户并发加入的新商品。
- 订单确认页使用 `_id + userId` 查询，不能通过修改 URL 读取其他用户订单。

## 地址与支付状态

地址保存失败不会回滚已经创建的订单，但服务端会记录错误；订单本身始终保留提交时的配送快照。

两种支付方式当前都创建 `paymentStatus: pending`、`orderStatus: pending` 的订单。后续 Stripe 阶段负责 PaymentIntent、Webhook、支付状态转换和失败恢复；后续订单管理阶段负责货到付款确认与履约状态。

## 库存边界

创建待支付订单不会预留或扣减库存。Stripe 支付确认阶段必须再次校验订单与库存，并使用事务或条件更新原子地完成库存扣减和状态转换。客户端显示的金额、订单快照甚至待支付订单本身，都不能替代支付前的服务端校验。
