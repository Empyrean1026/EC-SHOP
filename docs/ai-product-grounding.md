# AI Product Grounding (AI-P01)

AI-P01 adds a controlled, read-only product search boundary for a future shopping assistant. It does not connect to an LLM and does not add any user interface.

## Architecture

```text
Future AI assistant
  -> POST /api/ai/products/search
  -> AI Product Search Service
  -> existing Product Service
  -> MongoDB / Mongoose
```

The AI-facing service translates validated criteria into the existing `ProductListQuery`. Client input is never forwarded to `Product.find()` and cannot supply MongoDB operators.

## Request

`POST /api/ai/products/search`

```json
{
  "query": "デスク",
  "category": "home-living",
  "minPrice": 0,
  "maxPrice": 5000,
  "inStock": true,
  "limit": 5
}
```

All fields are optional. `inStock` defaults to `true`, `limit` defaults to `5`, and the maximum limit is `10`. Prices use the Product model's existing integer storage unit. Category values are existing category slugs.

Unknown but valid category slugs return an empty product array. Invalid slugs, negative prices, inverted price ranges, unknown fields, wrong data types, and limits above 10 return a 4xx response.

## Response

The project-wide API envelope is preserved:

```json
{
  "success": true,
  "data": {
    "products": []
  }
}
```

Each product exposes only:

- `id`
- `name`
- `slug`
- `description`
- `category.name` and `category.slug`
- `price` and `currency`
- `stock`
- the first `image`, or `null`
- a server-generated `url`

The product detail URL is generated by the shared URL helper. The DTO excludes Mongoose metadata, internal status, sales and review statistics, timestamps, and all user or administration data.

## Query behavior

- Only active products are returned by the existing Product Service.
- The default `inStock: true` condition maps to `stock > 0`.
- Keyword matching reuses the catalog's escaped name/description search.
- Category and price filters reuse the catalog query implementation.
- Results use the catalog's stable `sales_desc` order: `salesCount`, then `createdAt`, then `_id`, all descending.
- Empty results are successful responses, not server errors.

The endpoint returns public catalog facts only, so it follows the same read-access policy as the existing product listing. The global proxy still applies CORS checks and the existing search rate-limit policy.
