# 购物车系统

第六阶段使用 Zustand 管理浏览器中的即时购物车状态，并通过 Mongoose `CartModel` 为登录用户持久化数据。浏览器快照只负责交互体验，商品价格、库存与上架状态始终以服务端实时数据为准。

## 用户体验

- 商品列表和详情页均可加入购物车。
- 购物车支持增减数量、删除单项、二次确认后清空、商品小计与总金额。
- 数量受实时库存和单项上限约束；最多保存 100 种商品。
- 游客购物车保存在当前浏览器，刷新后仍可恢复。
- 登录或注册成功后，游客购物车自动与账户购物车合并。
- 商品下架、缺货或库存减少时，页面显示自动调整提示。
- 不同币种分别汇总，避免把不同货币直接相加。

## 状态与持久化

根布局中的 `CartProvider` 为每棵应用树创建一个独立 Zustand store。持久化中间件设置 `skipHydration: true`，组件挂载后才显式读取 `localStorage`，避免服务端渲染与客户端首屏不一致。

游客数据使用 `ec-guest-cart-v1` 保存。读取时会校验商品 ID、字段类型、数量、库存、重复项与容量，并重新计算小计。随后调用公开校验接口，用数据库中的最新商品信息替换本地快照。

登录用户的购物车仅在内存和 MongoDB 中保存，不写入 `localStorage`。账户操作先乐观更新界面；服务端失败时恢复旧状态并显示安全错误。退出登录只清除当前浏览器中的账户镜像，不删除 MongoDB 购物车。

若登录后的合并请求遇到临时网络错误，游客购物车会原样保留，下次加载时继续尝试，避免丢失用户选择。

## API

| 方法     | 路径                         | 权限        | 作用                     |
| -------- | ---------------------------- | ----------- | ------------------------ |
| `GET`    | `/api/cart`                  | 登录用户    | 获取账户购物车           |
| `DELETE` | `/api/cart`                  | 用户 + CSRF | 清空账户购物车           |
| `POST`   | `/api/cart/items`            | 用户 + CSRF | 添加商品或增加数量       |
| `PATCH`  | `/api/cart/items/:productId` | 用户 + CSRF | 设置商品数量             |
| `DELETE` | `/api/cart/items/:productId` | 用户 + CSRF | 删除单项                 |
| `POST`   | `/api/cart/sync`             | 用户 + CSRF | 合并游客与账户购物车     |
| `POST`   | `/api/cart/validate`         | 公开、只读  | 刷新游客购物车价格与库存 |

所有账户写操作都要求数据库中仍存在的用户会话、匹配的 `Origin` 和签名 CSRF Token。输入使用严格 Zod schema，商品 ID 必须是 MongoDB ObjectId，未知字段会被拒绝。单项请求体上限为 16 KB，批量同步和校验上限为 32 KB。

## 业务规则

- 单项数量范围为 1–99，并且不能超过当前库存。
- 一个购物车最多包含 100 种商品。
- 账户已有商品与游客同款商品合并时数量相加，再按库存和单项上限收缩。
- 账户原有商品优先保留；超过容量的新增游客商品会被忽略并返回调整信息。
- 不存在、下架和缺货商品不会出现在返回结果中。
- 商品名称、图片、价格、币种和库存由服务端重新读取，客户端提交的小计不会被信任。
- `GET /api/cart` 和游客校验不会隐式写数据库；下次合法写操作会保存已经收缩的结果。

接口可能返回 `PRODUCT_REMOVED`、`OUT_OF_STOCK`、`QUANTITY_REDUCED` 或 `CART_CAPACITY_REACHED` 调整代码，供客户端说明购物车为何发生变化。

## 结算边界

当前购物车不预留库存，多个用户仍可能同时购买同一商品。后续订单与 Stripe 阶段必须在服务端重新计算价格和总额，并通过事务或条件更新再次扣减库存；不得把购物车小计直接当作支付金额。
