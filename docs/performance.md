# 性能优化

## 图片

- 商品图和头像统一使用 Next.js `Image`，非首屏图片采用浏览器原生懒加载。
- 商品详情主图声明响应式 `sizes` 并预加载，降低 LCP；固定容器比例避免 CLS。
- 本地受信任图片由 Next.js 输出 AVIF/WebP，并缓存至少 4 小时。
- 管理员可填写任意 HTTP(S) 外部图片。为避免开放式图片代理和 SSRF/带宽滥用，未知远程源以 `unoptimized` 原样加载，但仍保留懒加载、异步解码和尺寸稳定性。生产环境若使用固定 CDN，可再将精确域名加入 `remotePatterns` 后启用服务端转换。

## 数据缓存

仅缓存与用户身份无关的公开目录数据：

| 数据                 |    TTL | 失效标签  |
| -------------------- | -----: | --------- |
| 商品列表、详情、搜索 |  60 秒 | `catalog` |
| 分类与商品数量       | 300 秒 | `catalog` |
| 搜索联想             |  30 秒 | `catalog` |

商品创建、编辑、库存更新和软下架成功后，Route Handler 使用阻塞式标签失效，下一次读取直接获得新数据。账户、购物车、订单、支付、Webhook、用户中心和管理员读取不进入共享缓存。

安全 nonce 需要请求时渲染，因此本阶段优化的是数据库查询缓存，而不是整页公共缓存。API 响应仍使用 `Cache-Control: no-store`，避免浏览器或共享代理保存含状态的数据。

## 分包与 React

- App Router Server Components 保持默认路由级代码分割。
- 管理员销售图表通过 `next/dynamic` 独立加载，Recharts 不进入统计页的初始客户端执行路径。
- 图表加载时展示固定尺寸骨架；趋势和热销商品派生数组使用 `useMemo`，避免币种交互时重复计算无关数据。

## MongoDB 与分页

- 商品公开列表、搜索、订单历史和管理员列表均使用服务端验证后的 `page` / `limit`、稳定排序、`skip` / `limit` 和独立总数查询。
- 商品页最大 50 条，搜索和管理员接口也有各自的最大页尺寸，防止一次请求读取无界数据。
- 新增库存筛选、用户订单状态、管理员订单双状态和用户角色/名称组合索引。
- 部署到目标数据库后运行 `npm run db:indexes`。该命令只创建模型声明的缺失索引，不删除既有索引。

大规模目录出现深页扫描瓶颈时，应在保持当前响应结构的同时迁移为基于 `_id` 或排序字段的 cursor pagination；当前 page 模式适合本阶段中小型目录和后台可跳页需求。
